\section{Verification and reproducibility}
The certificate consists of a JSON list of triples and one gzip member per
triple. The uncompressed bytes are the opcodes above. Lexicographic child
order supplies the implicit tree boundaries; reference targets are looked
up by image key and budget. The generator uses integer bitsets and forward
maximum path lengths. The Python checker uses sets and tracks each possible
extreme separately. The C++ checker stores a sorted union of distinct words;
weight recovers the layer. At each expanded or frozen node it scans the
gate list \emph{backwards}. Initially each port has destiny $(i,0)$. At a
reversed gate, for a given sign, let $(j,d)$ be the destiny of the extreme
output. Both input ports receive $(j,d+1)$. Backward induction gives the
terminal wire and encounter count for each starting position. No generator
code or stored node counts enter this calculation.

Both replays returned the counts in \cref{tab:counts}. The $(9,4)$ claim

all 26 compressed files and the generator's diagnostic log matched the
distributed copies byte for byte in the audit environment. The two

recurrence, sharing smaller-width dependencies.

An independent exhaustive search for $n\le6$ represents one output by
its entire Boolean truth table. At distance zero take all projections.
From $f$, visit $f\circ g$ for every ordered gate $g$. Induction on distance
identifies the frontier with the functions first reachable at that size:
prepending a gate composes the output in precisely this way. First discovery
of a rank threshold gives its minimum. This calculation uses no boundary
restriction, path pruning, wire symmetry or certificate. It returned the
costs in \cref{tab:counts} and their duals for all 20 ranks at widths two
through six. A separate simulation checked all $3^{11}=177\,147$ ternary
inputs. Deleting each single gate in turn produced 25 circuits with between
21 and 490 failing binary inputs apiece.

\section{Formal Verification in Lean 4}\label{sec:lean}
In Lean 4.19.0 a network is a list of oriented gates with distinct
ports of type \texttt{Fin n}. The semantics apply each compare--exchange
in sequence. Under \texttt{Standard}, the smaller value goes to the
lower-numbered port. The Boolean rank predicate counts zeros. For
ordered values, two counts compare each input with the output using
strict and non-strict comparisons, so the definition handles ties.

The kernel checks threshold reduction, boundary-layer constancy, the
three-encounter lemma, deletion via a moving wire bijection, rank
duality, and the recursive bound. It also checks the length and
orientation of Dobbelaere's witness, enumerates all $2^{11}$ Boolean
inputs, and proves correctness on every decidable total order in
\texttt{Median11.published\_selects}.

For a specification over a single ordered domain, choose two values
$a<b$ and encode each Boolean input by these values. Compare--exchange
commutes with this encoding, and the two rank counts are preserved
because the encoding reflects order. Thus correctness on that domain
implies correctness on the Boolean cube. Together with the witness this
gives exact size on every decidable total order containing a strict
pair. On a singleton domain the empty network already selects the median.

The kernel verifies the decoded proof data for all 26 exclusions in
\cref{tab:counts}. The list-based checker reduces the smaller preorder
replays directly. The packed checker uses natural-number bit masks for
sets of rows, with a proved correspondence to the list semantics. It
validates each expansion, including its gate images, pruning conditions,
and consumed interval. A memo reference checks the closed interval,
remaining budget and layer inclusion under one common wire permutation.
It can reuse an exclusion from an earlier prefix because that exclusion
quantifies over suffixes on the residual layers. The 167\,917-node
replay for $(9,4)$ is composed from 659 kernel-checked blocks.

\texttt{Median11.median11\_optimal} proves the fixed-wire exact-size
result without certificate premises. Its lower bound follows from
the two verified nine-wire exclusions and the deletion recurrence.
The archived eleven-wire exclusion gives a second checked derivation
of the numerical lower bound, using the same smaller-width bounds.
The three axiom dependencies reported for the exact-size theorem are
\texttt{propext}, \texttt{Classical.choice} and \texttt{Quot.sound}.
The Lean project uses core and Std.

Archive integrity and the translation from gzip bytes to Lean data
are checked outside Lean. The input generator preserves the opcodes
and proposes hints, including wire permutations and states at block
boundaries. The kernel checks the deductions those hints describe.
Python and C++ independently replay the unannotated archive. The
executable Lean replay provides another computational comparison.

With Lean 4.19.0 and Python 3.10 or newer on the path, run these commands
from the repository root:
\begin{verbatim}
bash scripts/verify-lean.sh
bash scripts/evaluate-lean-archive.sh
\end{verbatim}
The first checks source-data agreement, rebuilds the Lean project and
audits transitive axiom dependencies. The second executes the full replay.

\section{Scope and limitations}
The argument gives an exact size bound. It leaves optimal depth at
size 25, adaptive comparison cost, and separate min/max cost open.
Codish et al.\ use hybrid search and SAT for sorting \cite{codish}.
The historical SAT runs for the unrestricted size-24 instance here
returned unknown. The proof uses the combinatorial exclusion
certificate above. Certified SAT replay \cite{lrat} is a separate
approach.

The verification programs share a specification and an opcode stream,
so a common modelling error could affect all of them. Independent
implementation refers to how the replay algorithms were written and
executed within this project. Generative AI provided substantial
assistance with mathematical exploration, implementation,
verification, literature research, and manuscript preparation. This is
an internally reviewed computer-assisted preprint awaiting external
human peer review. The author is responsible for the mathematical claims
and approval of the manuscript. The witness is reproduced with attribution to
Bert Dobbelaere. Its source and upstream license are recorded separately
from the original manuscript's license.
